# 游戏模式与未来在线服务

- 文档版本：0.1
- 当前状态：需求保留，不属于局域网首阶段交付
- 原则：未来公网服务复用局域网的规则、命令、事件和录像格式

## 1. 模式总览

| 模式 | 首阶段 | 最终目标 | 权威节点 |
|---|---|---|---|
| Windows 单机 PvE | 支持 | 支持多难度 AI | 本地 Windows |
| 局域网聚会 PvP | 支持 | 支持完整扩展 | 本地 Windows |
| 局域网真人 + AI | 支持 | 支持掉线托管 | 本地 Windows |
| 公网好友 PvP | 不实现 | 2–6 人远程房间 | 公网服务器 |
| 公网匹配 PvP | 不实现 | 排位与休闲队列 | 公网服务器 |
| 混合聚会 | 不实现 | 本地手机与远程玩家同局 | 公网服务器 |
| PvPvE | 不实现 | 原创竞争合作模式 | 本地或公网权威节点 |

所有模式遵守所选官方规则集的人数限制。基础规则为 2–5 人，具有第六套玩家组件的规则集为 2–6 人。

## 2. PvE

### 2.1 首阶段基础 AI

- 只调用规则核心提供的合法动作。
- 不读取未来地块、其他玩家秘密选择或渲染数据。
- 可以完成抽取、放置、角色选择和终局。
- 在固定时间预算内稳定返回动作。
- 主要用于单人练习、缺席席位和断线托管。

### 2.2 后续难度

- 入门：偏好短期可见得分，允许可控次优选择。
- 标准：考虑随从效率、区域控制和地块概率。
- 专家：使用更大的搜索预算，考虑田野、阻断和长期资源。

难度只改变决策质量和搜索预算，不改变抽牌概率、可见信息或规则。

## 3. PvP

### 3.1 休闲模式

- 2–6 人好友房或公开房
- 房主选择已验证扩展
- 可选回合计时
- 允许观战、AI 填充和断线托管
- 结果记录在休闲战绩，不影响排位等级分

### 3.2 排位模式

- 首个排位规则集建议使用固定的双人基础规则。
- 规则版本、扩展、地块池和计时方式由赛季锁定。
- 一名账号对应一个正式席位。
- 共享设备、多本地席位和 AI 不进入排位。
- 完整保存随机状态承诺、操作日志、重连和判负原因。
- 新扩展只有通过平衡和兼容认证后才能成为排位规则集。

排位不应过早拆分为大量扩展队列，以免分散玩家池。

## 4. PvPvE

PvPvE 属于原创后续模式，不直接复刻某个现有合作产品。建议方向是“共同维持世界、竞争个人影响力”：

- 玩家继续通过道路、城市、修道院和田野竞争分数。
- 公共危机系统对未完成区域、补给路线或地图边缘施加压力。
- 玩家必须共同避免全局失败条件。
- 世界存续时，个人分数或影响力最高者获胜。
- 世界崩溃时，全体失败或按模式规则进行次级排名。

该模式必须使用独立规则 ID、计分说明和 AI，不得混入官方排位记录。

## 5. 账号

### 5.1 身份路径

- 本地临时档案无需注册。
- 用户未来可以将本地档案绑定到公网账号。
- 公网账号支持邮箱注册、验证、登录和找回。
- 第三方登录属于可选后续能力。
- 账号与显示昵称分离，允许在规则范围内修改昵称。

### 5.2 账号数据

- 稳定用户 ID 和身份凭据
- 昵称、头像和偏好设置
- 按规则集区分的等级分
- 休闲与排位战绩
- 对局历史和录像权限
- 成就和原创外观收藏
- 好友、屏蔽和邀请关系
- 举报、处罚和账号状态

密码、恢复凭据和会话令牌不得写入普通对局日志。

## 6. 持久化

公网对局至少保存：

- 对局 ID、房间 ID 和规则配置哈希
- 玩家与席位映射
- 随机种子或可审计的随机状态
- 权威事件日志和阶段快照
- 最终分数、排名和终止原因
- 重连、超时、投降和托管记录
- 录像可见性和保留策略

只保存最终棋盘不足以支持恢复、录像、争议复核和反作弊。

## 7. 匹配

匹配票据至少包含：

- 排位或休闲
- 规则集和扩展配置
- 玩家人数
- 单人或组队进入
- 地区和延迟范围
- 等级分与不确定度
- 计时方式
- 平台和输入限制，如有

搜索开始时使用较窄的等级与延迟范围，等待时间增长后按配置逐步放宽。不能把不兼容的规则集或人数请求强行匹配。

## 8. 在线对局生命周期

```text
登录
  → 创建匹配票据或好友房
  → 分配公网权威主机
  → 锁定席位与规则版本
  → 全员加载并确认
  → 开始对局
  → 权威记录操作、快照和重连
  → 完成最终计分
  → 更新战绩与等级分
  → 生成可见范围正确的录像
```

## 9. 计时、掉线和退出

- 休闲与排位使用不同的宽限和处罚配置。
- 切后台或网络切换不会立刻判负。
- 重连后恢复相同地块池、回合状态和剩余时间。
- 排位超时、主动退出和重复掉线需要明确的终止原因。
- 休闲房可允许 AI 临时托管；排位是否允许托管需要单独决定。
- 所有处罚由服务器依据权威日志产生，客户端不能自行申报胜负。

## 10. 混合聚会

未来允许一台 Windows 大屏连接公网，同时：

- 本地玩家通过手机加入不同席位。
- 远程玩家从其他设备加入。
- 大屏只显示公共状态。
- 公网服务器而非本地 Windows 判定规则。
- 本地局域网协调层负责把手机安全接入对应公网席位。

排位默认禁止同一聚会主机占据多个正式席位；好友休闲房可以允许。

## 11. 社交与治理

- 好友邀请和私人房间
- 屏蔽、静音和举报
- 快捷表情优先于开放文字聊天
- 录像和权威日志用于争议复核
- 房间名、昵称和聊天内容需要审核与限流
- 未成年人、个人数据和地区法规需要在上线地区确定后专项设计

## 12. 公网上线门禁

- 局域网和公网规则核心对同一录像产生相同结果。
- 服务端可以在客户端断开后独立完成超时和托管判定。
- 账号删除、导出和数据保留策略已经定义。
- 匹配不会把不同规则版本放入同一局。
- 排位结果只能由权威服务器生成一次。
- 私人状态不会发送给无权限的玩家、观战者或大屏。
- 公网故障不会破坏纯局域网和单机模式。
