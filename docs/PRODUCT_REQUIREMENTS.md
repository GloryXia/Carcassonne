# 产品需求文档

- 文档版本：0.1
- 状态：讨论基线
- 规则基线：当前基础版 + 2025 修订扩展系列
- 首发网络范围：局域网

## 1. 产品愿景

制作一款能够替代实体聚会桌游的数字地形拼接游戏：Windows 电脑驱动 4K 公共棋盘，玩家通过自己的手机参与，系统自动完成合法性判断、区域控制和复杂计分。它也应是一套可扩展的规则平台，能够逐步容纳官方扩展、AI、公网对战、3D 表现和 AR。

## 2. 产品原则

### 2.1 机制可信

- 同一规则版本、随机种子和操作序列必须产生相同结果。
- 每一次拒绝操作或获得分数都必须能够解释。
- 规则错误视为阻断发布的问题，不能以动画或 UI 规避。
- AI、本地玩家、手机玩家和未来公网玩家使用同一规则核心。

### 2.2 聚会友好

- 本地对局不强制账号、安装手机 App 或访问互联网。
- 从启动 Windows 客户端到第一位玩家开始回合，目标不超过 60 秒。
- 大屏承担公共信息，手机承担个人操作和隐私信息。
- 手机不可用时，玩家可以在 Windows 端继续操作。

### 2.3 表现可升级

- 规则层不引用模型、材质、动画或 AR 坐标。
- 首个可玩版本允许使用简洁 3D 或调试美术。
- 所有关键规则结果均发出语义事件，供后续特效订阅。

## 3. 目标用户与场景

### 3.1 客厅聚会

2–6 位玩家围绕电视游戏，Windows 主机显示棋盘，每人使用自己的手机控制席位。

### 3.2 单机练习

一名玩家在 Windows 端与 AI 对战；手机控制器是可选项。

### 3.3 教学与规则研究

玩家打开计分解释、区域连通高亮和回合日志，理解复杂的田野及扩展结算。

### 3.4 未来远程对战

本地大屏、本地手机和远程设备共同连接公网权威服务器。该场景不属于首阶段交付，但数据和协议必须支持迁移。

## 4. 平台与设备

### 4.1 Windows 主客户端

- 作为局域网权威主机运行完整规则引擎。
- 通过 HDMI 或扩展显示器输出 4K 公共画面。
- 本地保存房间、快照、操作日志和规则版本。
- 支持鼠标、键盘和可选手柄操作。
- 首次使用时引导用户允许必要的局域网防火墙访问。

### 4.2 手机控制端

- 兼容现代 iOS 和 Android 浏览器。
- 扫描二维码或输入短码加入。
- 不安装 App 也能完成基础游戏操作。
- 使用大尺寸触控目标，不依赖悬停或复杂手势。
- 原生 App、触觉反馈和 AR 属于后续增强。

### 4.3 电视

- 推荐 4K、55 英寸及以上。
- 电视只显示公共信息，不显示私人卡片或秘密选择。
- UI 需要适配 2–3 米观看距离、电视过扫描和 OLED 静态元素风险。

## 5. 游戏人数

- 当前基础游戏：官方 2–5 人。
- 启用包含第六套玩家组件的官方扩展规则集：官方 2–6 人。
- 真人与 AI 共同占用正式席位。
- 观战、房主后台和断线托管不额外增加玩家上限。
- 不实现七人自定义模式。

## 6. 首阶段游戏内容

### 6.1 必须实现

- 当前基础地块和完整基础规则。
- 农夫与田野终局计分。
- 河流小扩展。
- 修道院长与花园小扩展。
- 官方人数、组件数量和胜负规则。
- AI 席位的接口，以及至少一个可合法完成对局的基础 AI。

### 6.2 预留但不阻塞首个可玩版本

- 2025 修订的十大主要扩展。
- 当前小扩展和特殊地块形状。
- 历史版规则配置。
- PvPvE 原创规则。

## 7. 房间功能

### 7.1 创建房间

房主可以设置：

- 玩家人数与 AI 席位
- 玩家颜色
- 基础规则和已验证扩展
- 是否启用农夫、河流和修道院长
- 回合计时或不限时
- 断线宽限时间
- 是否允许 Windows 端代操作

### 7.2 加入房间

- 大屏显示二维码、短码和连接状态。
- 玩家输入昵称或选择已保存的本地档案。
- 房主批准、拒绝或移除设备。
- 一个席位同时只有一个主控制设备。
- 重连设备使用不可猜测的席位令牌恢复身份。

### 7.3 对局中

- 大屏显示公共棋盘、当前回合、公共计分和规则事件。
- 当前玩家手机显示地块、候选位置、随从和确认操作。
- 非当前玩家只能查看允许公开的信息和自己的组件。
- 房主可以暂停、保存、接管席位或启用 AI 托管。

## 8. 持久化与恢复

- 每个确认动作写入追加式事件日志。
- 定期及关键阶段保存状态快照。
- 快照包含规则版本、扩展清单、随机状态和动作序号。
- Windows 应用重启后可以恢复最近对局。
- 手机重新扫码后可以恢复原席位。
- 完成的对局可以回放并展示逐步计分。

## 9. AI

- AI 只能通过公开规则状态和合法操作接口行动。
- AI 不得读取未来地块或其他隐藏信息。
- 首阶段基础 AI 的目标是合法、稳定、及时完成对局。
- 后续难度通过评估函数、搜索预算和可控误差调整，不修改规则。

## 10. 画面、声音和 AR

### 10.1 首阶段

- 地块边界和区域连接必须清楚。
- 合法候选、当前区域、控制权和计分范围必须可视化。
- 动画可跳过，并提供减少动态效果选项。
- 3D 分辨率可以动态调整，UI 保持清晰。

### 10.2 后续

- 地形边缘融合、植被、建筑生长和计分特效。
- 原创模型、纹理、音效和环境表现。
- 单设备 AR 观赏、共享 AR 和 AR 交互。
- AR 丢失追踪时只退出 AR，不改变或暂停规则状态。

## 11. 公网预留

首阶段不实现账号、匹配、排位和云存档，但必须预留：

- 稳定的本地玩家 ID、对局 ID、房间 ID 和规则版本 ID
- 权威主机可替换的传输接口
- 命令、事件、快照和重连协议
- 本地档案绑定公网账号的迁移字段
- 按规则集区分的未来等级分和战绩字段

## 12. 非功能要求

- 规则结果必须确定性可复现。
- 局域网正常环境下，控制操作到大屏预览应无明显等待。
- 主机不能因为单个手机断线而中止对局。
- 4K UI 在目标观看距离下可读。
- 手机端基础操作符合无障碍触控尺寸，并提供文字和图形提示。
- 颜色不是唯一状态提示手段。
- 大屏与手机不得泄露不属于该设备的私人信息。

## 13. 首阶段不做

- 公网注册、登录、好友、匹配和赛季
- 商店、付费扩展和货币系统
- 语音聊天和公开聊天室
- 强依赖 AR 的玩法
- 未核验规则的扩展组合
- 七人或更高人数的自定义规则

## 14. 待确认事项

- Windows 客户端和手机网页的具体技术栈
- Windows 最低硬件与系统版本
- 手机是否需要在首阶段支持横竖屏切换
- 基础 AI 的首发强度标准
- 首阶段是否默认启用农夫、河流和修道院长
- 项目最终采用授权内容还是原创品牌与原创规则表述
