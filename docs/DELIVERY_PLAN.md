# 实施与验收路线

- 文档版本：0.1
- 原则：规则门禁优先，不以画面完成度代替机制完成度

本文描述交付顺序，不代表固定发布日期。每个阶段只有通过对应验收门禁后，才能成为下一阶段的稳定基础。

## 阶段 -1：技术风险验证

### 交付物

- 可复现的 Node.js/TypeScript、Godot 与 Web 工具链基线
- WSL2 默认 NAT、动态端口转发与 Windows 防火墙验证结果
- React、Godot 与 Game Host 的最小实时协议切片
- 确定性规则、SQLite 崩溃恢复和 4K 棋盘性能报告
- Windows Launcher 启动、诊断和原生 Host 降级方案

### 门禁

- 手机只使用 Windows 局域网 IP，即可通过动态转发连接独立 IP 的 WSL2 Host。
- WSL2 重启并改变 IP 后，Launcher 能自动刷新转发，不要求用户手工改地址。
- 强制完成 [技术验证计划](TECHNICAL_SPIKES.md) 的 Spike 0–5 与 Spike 7；Spike 6 条件执行，Spike 8–9 后置。
- 标准 WebSocket、Node.js SQLite 驱动、Godot、TypeScript 规则核心和 Windows Launcher 分别通过对应验收标准。
- D-014 经实测复核，D-015 被确认或由新的决策记录替换后，才创建正式产品工程。

## 阶段 0：规则与数据准备

### 交付物

- 冻结基础规则版本
- 逐块基础地块目录
- 区域拓扑数据规范
- 回合状态机
- 计分事件格式
- 官方示例与边界测试清单

### 门禁

- 72 块基础地块的数量和拓扑经过复核。
- 所有基础规则都有来源和测试映射。
- 文档不存在未标记的规则猜测。

## 阶段 1：无界面规则核心

### 交付物

- 地块抽取与旋转
- 合法位置枚举
- 地图和连接区域图
- 普通随从放置
- 道路、城市、修道院和最终计分
- 农夫与田野计分
- 确定性随机和事件日志

### 门禁

- 所有基础规则场景测试通过。
- 同一日志重复运行得到相同状态校验值。
- 无 UI 环境可以自动完成整局模拟。

## 阶段 2：Windows 单机可玩版本

### 交付物

- Windows 公共棋盘
- 鼠标键盘完整操作
- 清晰的合法位置与计分解释
- 本地房间和基础存档
- 简洁 3D 或调试画面

### 门禁

- 2–5 人轮流使用 Windows 输入可以完成基础对局。
- 应用重启后恢复正确状态。
- 关闭动画不影响任何规则或操作。

## 阶段 3：局域网手机控制器

### 交付物

- 二维码与短码加入
- 房主批准和席位管理
- 手机地块、旋转、位置和角色操作
- 权限过滤的公共与私人视图
- 断线重连和 PC 接管

### 门禁

- 多种 iOS、Android 浏览器完成整局对战。
- 六部手机并发连接时主机保持稳定。
- 非法、重复和过期命令均被正确拒绝。

## 阶段 4：基础内容完整化

### 交付物

- 河流
- 修道院长与花园
- 第六套玩家组件及官方六人规则配置
- 可合法完成游戏的基础 AI
- 回放、详细计分和规则帮助

### 门禁

- 2–6 人混合真人与 AI 可以完成对应官方规则集。
- 河流和修道院长官方示例全部通过。
- 完整录像可以逐事件重放并恢复终局分数。

## 阶段 5：主要扩展平台

按扩展 1 至 10 逐个推进。每个扩展独立经历：

1. 官方规则和组件核验
2. 地块与角色录入
3. 回合阶段和事件设计
4. 手机交互设计
5. 规则实现
6. AI 动作接口
7. 官方示例测试
8. 与已支持扩展的兼容测试

达到验证级之前，不在普通房间显示该扩展。

## 阶段 6：表现升级

### 交付物

- 原创地形、建筑和角色资产
- 地块边缘融合
- 放置、完成和计分动画
- 环境音效和音乐
- 动态质量、低功耗和减少动画模式

### 门禁

- 中低端目标电脑可以稳定输出可读的大屏画面。
- 视觉效果不会遮挡合法位置、角色或计分信息。
- 使用占位资产和最终资产得到相同规则回放结果。

## 阶段 7：AR

### 交付顺序

1. AR Lite：完成地图的单设备放置与摄影
2. Shared AR：多设备公共锚点
3. Interactive AR：空间预览和选择

### 门禁

- AR 关闭或失去追踪不影响对局。
- AR 选择仍由权威逻辑网格验证。
- 不支持 AR 的玩家可以加入同一房间。

## 阶段 8：公网服务

### 交付物

- 账号、身份绑定和云档案
- 在线房间和好友邀请
- 匹配、排位和赛季
- 公网权威主机
- 远程重连、举报和审计
- 本地与远程玩家混合房间

### 门禁

- 局域网历史录像可由公网规则核心重放。
- Windows 和手机控制协议无需大规模改写。
- 本地模式在公网服务不可用时仍能完整运行。

## 测试体系

### 规则单元测试

- 地块旋转和边缘匹配
- 地块内部拓扑
- 区域合并、完成和控制权
- 每种计分公式
- 扩展触发器和优先级

### 场景测试

- 官方规则书示例
- 人工构造的边界棋局
- 多区域同时完成
- 多玩家并列与最终同分
- 扩展组合冲突

### 性质测试

- 不合法操作不改变状态
- 一个地块实例只在一个位置出现
- 得分事件总和等于玩家分数变化
- 已归还角色不再属于地图区域
- 重放事件不依赖动画和时钟

### 网络测试

- 消息重复、乱序、延迟和丢失
- 手机断线与快速重连
- 主机重启恢复
- 多设备争抢同一席位
- 权限过滤和私人数据泄漏

### 长时间测试

- 六人完整大地图
- 多局连续建房与销毁
- 长时间电视显示
- 多次保存、恢复和回放

## 当前下一步

在开始功能开发前，需要优先完成：

1. 在目标 Windows 11 + WSL2 电脑上强制执行技术验证 Spike 0–5 与 Spike 7；按条件决定是否执行 Spike 6。
2. 根据实测结果复核 D-014，并确认 D-015 或用新的决策记录替换未通过方案。
3. 获取锁定版本的基础地块组件表，并建立 72 块基础地块的逐块拓扑目录。
4. 将基础规则转成可执行的状态机测试场景表，再创建正式工程骨架。
