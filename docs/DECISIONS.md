# 决策日志

本文记录已经确认的产品决策。修改已确认决策时，需要新增一条记录并说明原因，不直接抹去历史。

## D-001 机制优先

- 状态：已确认
- 决策：规则、计分、拓扑和联机一致性优先于画面与特效。
- 影响：规则引擎必须能够脱离 3D 引擎运行；表现层只消费语义事件。

## D-002 官方规则人数

- 状态：已确认
- 决策：基础规则支持 2–5 人；具有第六套玩家组件的官方规则集支持 2–6 人；不提供七人模式。
- 影响：房间创建、AI 席位、地块池和扩展选择均按照所选官方规则集限制人数。

## D-003 当前规则基线

- 状态：已确认
- 决策：主规则以当前基础版及 2025 修订扩展系列为准。
- 影响：旧版 C1/C2 差异只做资料记录或显式的旧版规则配置，不能静默混入默认规则；当前版规则在内容清单中使用正式版本与规则集哈希标识，不依赖社区简称。

## D-004 Windows 局域网主机

- 状态：已确认
- 决策：第一阶段由 Windows 电脑同时承担权威主机、持久化节点和大屏渲染客户端。
- 影响：游戏在无互联网环境下必须完整可用；手机不承担规则判定。

## D-005 4K 电视公共画面

- 状态：已确认
- 决策：4K 电视是推荐公共棋盘，通过 Windows 主机的 HDMI 或扩展显示器输出。
- 影响：电视 UI 面向 2–3 米观看距离设计，并提供自动聚焦、全局概览和安全边距。

## D-006 手机作为个人终端

- 状态：已确认
- 决策：每位玩家可以使用 iOS 或 Android 手机加入本地对局，查看个人信息并提交操作。
- 影响：首阶段提供无需安装和登录的轻量手机网页；PC 鼠标键盘仍是必要降级方案。

## D-007 局域网优先、公网预留

- 状态：已确认
- 决策：先完成纯局域网模式，不在首阶段实现注册、匹配和公网房间。
- 影响：命令、事件、快照和身份模型不能依赖进程内调用，未来可将权威主机替换为云服务。

## D-008 3D 与 AR 是可选表现层

- 状态：已确认
- 决策：基础画面先保证清晰与稳定；地形融合、环境效果和 AR 在规则稳定后逐步实现。
- 影响：不开启特效或 AR 时，玩法、计分和随机结果完全一致。

## D-009 本地无需账号

- 状态：已确认
- 决策：本地玩家可以使用临时昵称直接加入，不得以注册或互联网连接作为开始对局的前置条件。
- 影响：本地档案使用稳定的本地玩家 ID，未来允许绑定公网账号。

## D-010 公开发行边界待定

- 状态：待决定
- 决策：当前按内部原型和规则研究项目推进；是否获得授权或转为原创品牌尚未决定。
- 影响：不得将工作名称、官方视觉资产或规则原文直接视为可公开发行内容。

## D-011 WSL2 是一等主机环境

- 状态：已确认
- 决策：Windows 电脑允许使用 WSL2 承载规则主机、局域网服务、SQLite 和手机前端静态文件；Windows 原生层负责 Godot 和 4K 渲染。
- 影响：局域网协议不能依赖单进程。WSL2 保持默认 NAT 和独立 IP；Windows Launcher 动态获取 WSL IP，并维护 Windows 局域网端口到 WSL 的转发和防火墙规则。原生 Windows 后端保留为兼容部署方式，而不是另写一套主机。

## D-012 推荐技术栈

- 状态：已废弃，由 D-014 取代
- 决策：规则核心和主机优先采用 C#/.NET 10；手机控制器优先采用 React/TypeScript；Windows 3D 显示优先采用 Godot .NET；本地持久化优先采用 SQLite。
- 影响：在完成技术验证前不创建大规模业务代码。若 Godot 4K 或 WSL2 局域网验证失败，按照技术栈调研文档中的备选方案重新决策。

## D-013 实时协议

- 状态：已废弃，由 D-015 取代
- 决策：HTTP 负责引导、健康检查和快照，ASP.NET Core SignalR 负责实时命令与事件，首阶段负载使用带版本的 JSON。
- 影响：需要验证 Godot .NET 客户端兼容性、六部手机重连和协议顺序；失败时回退为同一消息模型之上的原生 WebSocket，而不改变领域命令和事件。

## D-014 Node.js/TypeScript 技术栈

- 状态：已确认
- 决策：权威 Game Host、规则核心、协议契约和 SQLite 访问统一采用 Node.js 24 LTS 与严格 TypeScript。首阶段不使用 .NET；Godot 使用标准版/GDScript，Windows Launcher 使用随产品携带运行时的 TypeScript/Node.js。
- 影响：规则与前后端可以共享 TypeScript 类型和测试夹具；Godot 通过 JSON Schema 和契约测试接入。所有确定性规则测试必须覆盖 JavaScript 安全整数、位运算、规范序列化、集合顺序和随机算法。

## D-015 标准 WebSocket

- 状态：提议，等待技术验证
- 决策：Fastify HTTP 负责静态页面、引导、健康检查和快照；标准 RFC 6455 WebSocket 负责实时命令与事件；首阶段使用带版本的 JSON，不采用 SignalR 或 Socket.IO 私有协议。
- 影响：浏览器使用原生 WebSocket，Godot 使用 `WebSocketPeer`。心跳、幂等、事件补发、快照恢复和慢客户端处理由项目协议实现；服务端 WebSocket 包可替换而不改变领域消息。
